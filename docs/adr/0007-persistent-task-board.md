## Context and checks before the initial selection

Pi Web requires Node >=22.19.0 and distributes a compiled Next application through its existing local/global packaging flow (`package.json`, `next.config.ts`, `bin/pi-web.js` and [distribution contract](../branch-features/local-global-install.md)). The checkout already uses proper-lockfile 4.1.2 (MIT) and serializeByKey for route-bundle/HMR coordination. fs, crypto and same-directory atomic rename are available below the minimum Node version. No dependency, native ABI, executable, global installation or licensing change was needed.

The initial host was macOS/Node26; minimum-version execution, Windows and production-package execution were not tested. SQLite would add unnecessary native/package/runtime constraints to this personal foundation. Session JSONL and browser storage cannot serve as task databases: tasks must exist without sessions, persist across clients/processes and not scan conversation bodies.

## Decision (initial foundation, still retained)

- Store one versioned document at `<agent-dir>/tasks/board.json`, separate from native session files. The initial shape was version1/tasks; it is not today's schema. HTTP resolves agentDir through the existing SDK; tests supply a real temporary agentDir.
- Use existing keyed serialization and proper-lockfile for every read/edit/initialization. Write a synced mode0600 same-directory temporary file and rename. Initialize only a missing store; invalid/unreadable/unsupported versions are refused without overwriting.
- `task-store.ts` version dispatch is the explicit locked migration entry. At ticket01 selection there was no legacy task schema; subsequent versions now have published migrations governed by the feature contract. No invented v0 or isolated source-only format inference.
- `taskOperation` is the sole semantic entry with strict input validation, server-resolved project identity, immutable create-ID idempotency and independent revision checks. HTTP and authorized callers do not write the file directly. Existing authentication/file/tool/model rules remain authoritative.

## Retained consequences and limits

This is an O(n) personal-board document capped at32MiB before commit, not a general relational/index/query framework. Locks retry about3s/stale30s; failures surface as unavailable, never an empty board/reset. Unconfirmed requests retain their exact identity; stale conflicts require explicit new intent, not silent rebase. Unsupported formats require compatible code/explicit migration, not a reset or downgrade repair.

No backup/repair UI or second persistence engine is introduced. Tasks/knowledge/relationships are separate from native histories; board/JSONL writes are **not a cross-file transaction**. Pi Web's single-process wrapper admission does not sandbox external CLI or arbitrary trusted extensions bypassing it. N1 existing external-delete+set_tools headerless/500 behavior remains a known P2; unknown copies may leave duplicate/orphan native children.
