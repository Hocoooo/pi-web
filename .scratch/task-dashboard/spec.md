# Pi Web 任务看板与共享重点：正式需求说明

Status: ready-for-agent
Type: spec
Blocked by: none

产品范围：个人使用的第一版。
依据：八轮访谈的 31 项选择、用户“理解一致”的整体确认，以及对三层验收方式的确认。
代码调研基线：85cc4f3。
状态说明：本规格可用于拆分实施票据；不表示功能已实现、测试已通过，或已授权自动执行、启动子代理、提交代码和远程发布。

## Problem Statement

用户同时在多个项目和多段 AI 对话中工作，但缺少以“要完成的一件事”为中心的组织方式。仅看对话列表，很难知道哪些任务还没开始、哪些正在做、哪些遇到问题、哪些等待检查。

同一任务往往需要研究、实现、检查等多段对话。新的对话不知道之前已经确定的目标和决定，用户只能反复解释或手动复制历史。直接共享全部记录又会夹带无关尝试、过时结论或敏感内容。

用户需要一个可拖拽、可筛选的任务看板，把相关对话放在同一任务下，并让这些对话使用经过自己确认的共享重点。任务状态与 AI 是否正在工作必须分开，避免把一次运行结束误判为任务完成。

## Solution

在现有 Pi Web 中新增独立任务看板页面，保留原有聊天入口和使用方式。任务可以属于一个项目，也可以没有项目；一个任务可以关联多段对话，每段对话最多属于一个任务。

看板默认提供待办、进行中、待检查、受阻、已完成五列，所有项目共用。用户可以调整列、拖动任务、使用自动排序、组合筛选并保存筛选条件。所有任务状态由用户修改，AI 只能建议；拖动卡片不启动 AI。

任务可以在看板创建，也可以从聊天创建。点击“开始执行”后，用户选择新建或继续旧对话，检查准备发送的内容，再独立发送。允许多段对话同时工作，但共用代码目录时须提示冲突风险。

用户主动点击“整理共享重点”，选择参考对话和可选工具结果，预览、删减资料并确认模型后生成摘要。摘要可编辑，只有用户确认后才成为共享重点。保留每次确认后的版本，支持查看和恢复。新建任务对话默认采用最新确认版本；已有对话由用户选择接收，且不打断正在进行的工作。

任务不再需要时可以归档和恢复，对话与共享重点保留。有 AI 正在工作时不能归档。第一版不提供任务彻底删除、团队协作或自动调度。

## User Stories

以下故事中的“用户”均指个人部署的使用者；编号用于规格覆盖和测试引用，不是实施票据。

1. 作为用户，我希望在独立页面查看任务看板，以便集中管理工作而不改变原有聊天界面。
2. 作为用户，我希望查看所有项目的任务并筛选单个项目，以便兼顾总览与专注处理。
3. 作为用户，我希望创建不属于项目的任务，以便组织资料研究等普通聊天工作。
4. 作为用户，我希望一个任务最多属于一个项目，以便明确工作范围。
5. 作为用户，我希望一个任务关联多段对话，以便分别开展研究、实现和检查。
6. 作为用户，我希望每段对话最多属于一个任务，也允许不关联任务，以便保留自由聊天方式。
7. 作为用户，我希望在看板创建任务，以便先计划再开始工作。
8. 作为用户，我希望从现有聊天创建任务，以便把临时讨论转成正式工作。
9. 作为用户，我希望手动选择多段旧对话关联到任务，以便批量整理历史而不让 AI 自行归类。
10. 作为用户，我希望系统拒绝跨项目关联，以便不把另一个项目的信息误带入任务。
11. 作为用户，我希望同一项目不同代码副本中的对话仍能关联同一任务，以便独立开展相关工作。
12. 作为用户，我希望无项目任务只关联无项目聊天，以便任务归属规则保持一致。
13. 作为用户，我希望在任务详情打开关联对话后进入原聊天页面，以便继续使用已有聊天功能。
14. 作为用户，我希望对话停止工作后可以解除或改绑任务，以便修正错误归类。
15. 作为用户，我希望改绑前知道旧任务信息仍留在聊天里，以便需要隔离时选择新建对话。
16. 作为用户，我希望复制或另开分支形成的新对话默认沿用原任务，以便尝试不同方案时无需重新归类。
17. 作为用户，我希望普通新建空白聊天不自动关联任务，以便不误带入之前的工作内容。
18. 作为用户，我希望初始看板包含待办、进行中、待检查、受阻和已完成，以便区分实际工作阶段。
19. 作为用户，我希望所有项目共用一套状态列，以便在总览中使用一致的规则。
20. 作为用户，我希望增加未完成列、修改列名和调整列顺序，以便适应自己的工作习惯。
21. 作为用户，我希望完成列改名后仍代表完成，以便显示文字不改变任务含义。
22. 作为用户，我希望保留一个不能删除的完成列和至少一个未完成列，以便始终能够表达任务是否完成。
23. 作为用户，我希望删除仍有任务的其他列时先选择接收列，以便不丢任务或被自动改到不合适的位置。
24. 作为用户，我希望通过拖拽跨列改变状态、在手动排序时调整列内位置，以便直观整理任务。
25. 作为用户，我希望拖动卡片不启动 AI，以便整理看板不会意外执行操作或产生推理费用。
26. 作为用户，我希望全部任务状态只由自己修改，以便 AI 的建议不会直接改变工作记录。
27. 作为用户，我希望 AI 停止、失败或自行声称完成时任务不会自动完成，以便保留自己的检查步骤。
28. 作为用户，我希望按文字、项目、状态、优先级、标签和 AI 是否正在工作筛选，以便快速找到要处理的任务。
29. 作为用户，我希望保存筛选条件并再次打开，以便无需重复设置常用视图。
30. 作为用户，我希望切换手动排序与按优先级、最近更新等自动排序，以便根据不同目的查看任务。
31. 作为用户，我希望自动排序时暂停列内拖拽调序但保留跨列移动，以便排序规则不会与拖动操作互相抵消。
32. 作为用户，我希望筛选后移动卡片不影响隐藏任务的归属或丢失它们，以便安全地整理局部视图。
33. 作为用户，我希望卡片显示标题、优先级、标签、项目、对话数量、AI 工作提示和更新时间，以便不打开详情也能了解进展。
34. 作为用户，我希望任务详情包含详细说明、完成要求、对话列表和共享重点，以便找到完整工作信息。
35. 作为用户，我希望点击“开始执行”后选择新建或继续旧对话，默认新建，以便选择合适的工作起点。
36. 作为用户，我希望检查任务信息和准备发送的内容后再独立发送，以便打开任务或准备对话不会直接启动 AI。
37. 作为用户，我希望同一任务的多段对话可以同时工作，以便并行研究或检查。
38. 作为用户，我希望使用同一代码目录并行工作前看到风险提示，以便知道文件可能互相覆盖并选择独立目录。
39. 作为用户，我希望 AI 工作状态以独立标记显示，以便它不会被误认为任务状态。
40. 作为用户，我希望仅在自己点击时才整理共享重点，以便控制整理时机和额外模型费用。
41. 作为用户，我希望勾选整理所参考的对话，从聊天发起时默认选当前对话，以便排除已经放弃或不相关的讨论。
42. 作为用户，我希望整理资料默认使用选中对话的文字交流，并允许额外勾选工具结果，以便按需加入测试或命令证据。
43. 作为用户，我希望整理不会自动读取附件和文件全文，以便引用文件名不会变成读取或上传文件的授权。
44. 作为用户，我希望发送给整理模型前预览和删减资料，以便移除不必要或敏感的信息。
45. 作为用户，我希望从聊天发起整理时默认使用该对话的模型，从看板发起时使用全局默认模型，以便减少重复选择。
46. 作为用户，我希望整理前看到模型并允许临时更换，以便权衡效果、费用和资料发送对象。
47. 作为用户，我希望临时模型选择不修改原对话或全局设置，以便辅助整理不影响正常工作。
48. 作为用户，我希望整理结果包含目标、已做决定、完成情况和下一步，并允许手动修改，以便纠正摘要遗漏或错误。
49. 作为用户，我希望只有确认后的内容才成为共享重点，以便未审核的 AI 总结不会传播。
50. 作为用户，我希望保留每次确认后的共享重点版本，能够查看和恢复，以便追溯或纠正之前的决定。
51. 作为用户，我希望新建任务对话默认使用最新确认版本，以便无需重新解释已确定的事情。
52. 作为用户，我希望已有对话收到共享更新提醒但不自动接收，以便自己控制其工作依据。
53. 作为用户，我希望运行中的对话接收更新后显示“下次使用新版本”，直到本次结束、下次发送才采用，以便不中断当前工作。
54. 作为用户，我希望共享重点不是全部聊天记录的拼接，以便减少无关内容和过时结论。
55. 作为用户，我希望看见共享重点的来源和采用版本，以便知道对话依据了哪些信息。
56. 作为用户，我希望不再需要的任务可以归档并恢复，以便减少看板杂乱而不丢历史。
57. 作为用户，我希望归档保留对话和共享重点，归档任务仍可查，以便之后继续或回顾。
58. 作为用户，我希望有关联 AI 正在工作时不能归档，以便任务不会隐藏后仍悄悄运行。
59. 作为用户，我希望归档不会替我停止 AI 或把任务标为完成，以便这些不同操作仍由自己明确决定。
60. 作为用户，我希望刷新、服务重启后任务和共享版本仍在，以便看板不是一次性的浏览器状态。
61. 作为用户，我希望两个页面同时修改时不会静默覆盖或重复执行操作，以便多标签页工作可靠。
62. 作为用户，我希望操作失败有明确反馈且不会伪装成成功，以便知道哪些更改真正保存。
63. 作为用户，我希望键盘和手机也能完成看板的核心操作，以便不依赖桌面鼠标拖拽。
64. 作为用户，我希望新增看板不改变原聊天的工具权限、模型设置和历史，以便现有工作可以照常继续。
65. 作为用户，我希望自动测试使用临时资料和模拟模型，以便验证功能时不改动真实聊天或默认产生模型费用。

## Implementation Decisions

本节区分已确认的产品规则、为满足规则所需的工程约束与仍待验证的技术选型。不把推荐库或研究报告中的设想视为已获批准的实现。

### D1. 任务是独立的长期记录

- Task、Session、共享重点和任务状态采用已确认词汇；任务不等于 session 内的执行步骤清单。
- 一个任务最多属于一个项目，一个对话最多关联一个任务；允许双方存在无关联状态。
- 任务元数据、任务与对话关系及共享版本独立持久化；原生对话历史继续由现有会话机制管理，不复制或重写成任务数据库里的第二份历史。
- 任务标题、对话标题、目录 basename 都不作为身份键；项目判断复用现有服务端身份和跨平台路径规则。
- 无项目聊天继续使用现有固定聊天工作区，不能因为关联任务而改变权限或被强制改成 Chat-only。

### D2. 以统一任务操作入口集中规则

- 新增任务应用模块，通过一个主要 Interface 处理创建、编辑、移动、关联、归档和共享版本操作。
- 页面与后台请求使用同一套规则；不要让组件、路由和会话接入分别实现一套状态判断。
- 优先复用已有会话读取、创建、发送、分支、模型选择和运行状态能力，不引入第二个 Agent 引擎。
- 新模块对外返回明确成功、冲突、范围不允许或忙碌等结果，不要求调用方了解存储细节。
- 这是用户确认的主要测试入口；内部存储与模型调用可以替换以支持临时环境和模拟测试，不为尚不存在的多种后端提前做泛化框架。

### D3. 看板与列

- 独立看板页面与原聊天页面切换；不实现看板/聊天并排布局，也不替换原首页和历史聊天入口。
- 列初始顺序为待办、进行中、待检查、受阻、已完成；所有项目及无项目任务共用。
- 完成列只有一个，以稳定身份而非显示名称表达完成；可改名和调序，不能删除。新列均属未完成，至少保留一个未完成列。
- 删除允许删除的非空列前，用户必须明确选择接收列；转移覆盖该列所有任务，包括筛选隐藏或已归档的任务，不只处理当前可见卡片。
- 删列和任务转移应表现为一个完整操作，不能成功一半。选择完成列作为接收列时，明确告知这会把相应任务标为完成，不能把该结果藏在一般配置操作中。
- 卡片与详情内容按故事 33、34；标签和优先级是可维护的任务属性，不是只读装饰。

### D4. 状态、排序和筛选

- 所有任务状态只由用户主动操作改变；发送消息、Agent 开始或停止、模型输出、工具结果和归档都不能自动推进状态。
- 移入完成列属于用户确认完成的操作；AI 说“完成”仅是对话内容或建议。
- 手动排序与自动排序分开。自动排序时列内调序不可用，但允许跨列改状态；切换排序方式不损坏已保存的手动顺序。
- 筛选不得改变数据归属；局部视图的拖动只移动指定任务，不能用可见数组替换全部任务。
- 保存筛选条件应能在之后重新打开。优先级和自动排序的具体展示格式、排序同值规则在实现中采用确定性规则并测试，不作为新一轮产品访谈问题。
- 服务端验证移动请求，处理重复提交和并发冲突；前端可先展示操作结果，但保存失败必须回滚或重新同步，不能静默丢更新。

### D5. 对话关联与运行

- 在看板或聊天中创建任务；旧对话支持手动批量关联，不做自动聚类或 AI 推荐聚类。
- 项目任务只接受同项目对话；无项目任务只接受无项目聊天。同项目不同工作目录或代码副本仍按现有项目身份判断。
- 改绑须在对话停止工作后进行，并再次验证项目范围。改绑不改工作目录，不删除旧消息，也不承诺清除模型已读信息。
- 复制或另开分支形成新 session 时继承原任务关系。仅在原 session 内切换分支，不凭空创建新的任务关系。
- 普通空白聊天不自动归属任务；无关联的源对话复制后也不凭空关联任务。
- 从任务开始执行默认新建，也可继续旧对话。仅准备内容不发模型请求，实际发送使用现有准入与错误处理。
- 新 session 的任务关联及待用共享版本必须在首条实际消息被接受前确定；关联失败不得继续发送带错任务信息的消息。
- 允许并行；同目录风险提醒不宣称拥有写入锁、文件隔离或自动合并能力。
- 工作中、等待交互、失败等会话信息与任务状态分开。判断是否还在工作沿用现有运行生命周期，不能把首个结束事件当作整个队列已停止。

### D6. 归档

- 第一版只有归档和恢复，没有任务彻底删除。
- 归档从日常看板隐藏，历史仍可查，恢复后仍保留任务状态、对话关系和共享版本。
- 归档不得隐式标记完成、停止运行或删除对话。
- 有关联 AI 正在工作时拒绝归档；执行时必须重新检查，不能只依赖页面上的旧徽标。
- 工作启动与归档竞争时，统一任务操作入口必须给出一致结果，不允许两项操作都基于过期状态通过而违反规则。
- 归档任务需要先恢复再从任务入口发起新工作；原聊天入口若可能启动其关联对话，也必须明确要求恢复，不能绕过“不隐藏仍在工作任务”的约束。
- 上述保证针对 Pi Web 管理的操作，不宣称控制任意外部进程或操作系统文件写入。

### D7. 整理共享重点的输入与模型

- 整理仅由用户点击触发；打开页面、运行结束、切换对话或查看历史均不自动生成。
- 参考范围由用户勾选对话；从聊天发起时默认当前对话。文字交流与额外选中的工具结果组成可预览、可删减的输入。
- 采用选中对话的明确分支和已完成记录；不混入隐藏分支、正在流式生成的半条输出、未选工具结果、系统提示、raw thinking 或后台 scratchpad。
- 不因消息中出现路径、链接或附件就读取其内容。工具结果中已经含有文件文字的，要作为选中资料清楚展示，不能伪称它不含文件内容。
- 预览后锁定实际发送的资料和所选模型；后台新增消息不能偷偷扩大已预览的输入范围。超出模型容量时提示缩减或明确呈现处理结果，不静默丢掉关键约束。
- 从聊天发起默认该对话的模型，从看板发起默认全局模型；显示选择并允许临时更换，不更改来源对话或全局设置。
- 使用现有模型可用性与凭据策略。选定模型不可用时明确失败，不静默换模型发送资料或收费。
- 整理是独立辅助生成，不调用来源 session 的普通 prompt，不运行工具，不改变其历史、队列或权限。
- 用户会被告知资料将发送给所选模型服务，可能产生费用；可以预览和删减，但不保证自动发现并移除所有敏感信息。

### D8. 确认、版本与恢复

- AI 的输出首先是待审核内容，不是已共享事实；用户可以编辑，也可以放弃，不自动分发给其他对话。
- 共享重点包括目标、已做决定、完成情况和下一步，不是原始历史的大段合并。
- 每次用户确认形成独立版本，保留来源引用与生成信息；修改未确认前不替换已确认版本。
- 恢复旧内容也通过用户确认形成新的当前版本，不抹去之后发生过的历史，避免破坏版本追踪。
- 两个页面基于同一旧版本分别发布时，识别冲突并保留待处理内容，不静默用后一个覆盖前一个。
- 整理或发布失败不会破坏已有确认版本，也不会把半成品当作最新共享重点。

### D9. 对话如何采用共享重点

- 新建任务对话默认使用发送时明确选定的最新确认版本；仍遵守发送前检查，不在浏览或准备阶段自动启动 AI。
- 已有对话只提示有更新，用户点击后才选择接收的版本。未点击不自动追新。
- 接收时若正在工作，只登记待采用版本；不发 steer、follow-up，不停止或重启当前运行。
- 待采用版本在本次工作结束、下一次用户发送时使用；如果还有更晚版本，不未经用户同意改用更晚版本。
- 界面区分已采用与下次采用的版本，实际发送过程记录使用的任务和版本，便于解释来源。
- 注入采用 SDK 支持的普通上下文能力，标明资料来源和版本；不把外部资料伪装成更高优先级的系统指令。
- 不通过覆盖只读会话状态或手工合并 JSONL 实现共享；不破坏工具调用与结果配对、分支、压缩和精确系统提示合同。
- 改绑或解除关联后停止读取旧任务的新版本并清除不再适用的待采用引用；已进入对话的文字仍保留，不能承诺撤回既有知识。

### D10. 数据可靠性、访问与兼容

- 任务、列、顺序、关联、已保存筛选和共享版本需要跨刷新、重启保存；不能仅依赖浏览器内存。
- 延用现有 Web 认证和文件授权，服务端再次校验 task/session/project 范围；目录引用不自动扩大访问权限。
- 用户选择的数据才用于整理；其他任务、项目或未选记录不因搜索便利而被加入。
- 任务列表使用轻量会话信息，正文按需读取；看板不能为每张卡扫描完整历史或启动一个休眠会话。
- 多标签页变更和断线后重新打开应最终回到服务端已保存状态；增量通知不是持久化成功的唯一依据。
- 保留现有项目侧栏、独立聊天、草稿与导航、会话分支、工具预设和模型设置行为。
- 键盘与触摸有等价核心操作，不把鼠标拖拽作为唯一入口。保持当前 Windows、macOS 和旧 Safari 支持要求。

### D11. 技术选型尚未锁定

- 保留现有 Web 栈与 Pi 会话引擎。
- 拖拽库、具体存储引擎、迁移机制及上下文投递的具体 SDK 接法，在实施票据中先核实兼容性并记录结果。
- 调研中的 dnd-kit、Pragmatic Drag and Drop、SQLite 等是候选，不是本规格对某个版本或库的强制采用决定。
- 选择必须满足现有最低运行环境、全局安装分发、平台兼容、许可和本规格的一致性要求；工程验证失败时不能悄悄删减已确认产品行为。
- 不为技术选型变化重开已确定的产品访谈；若验证证明必须改变用户行为或数据发送范围，再提出具体变更。

## Testing Decisions

用户已确认三层验收：任务操作、与现有对话配合、实际页面操作。测试通过对外可观察的结果验证行为，不用函数名、内部调用次数或源文件字符串代替功能验收。

### 主要测试入口与现有参考

1. **任务操作层**：通过统一任务应用模块的公共操作运行测试，使用真实临时存储，检查重新读取和重开后的结果。不要把每个内部函数都做成独立测试入口。
2. **对话配合层**：复用已有会话创建、生命周期、分支和模型调用接口；使用临时 agent-dir、真实 SDK 会话和合成历史，在 provider 接口使用可记录输入的模拟模型。现有独立聊天与会话生命周期测试提供此模式。
3. **页面操作层**：沿用现有 Playwright 浏览器回归方式，测试完整用户流程、桌面与移动布局。现有浏览器套件覆盖临时会话、分支和访问范围，但不能据此假设它已经覆盖模型请求与新看板。
4. 辅助生成参考现有“下一轮提示词建议”测试中独立调用模型、来源分支、临时模型不改原设置和过期结果保护的做法；新整理功能的输入范围与交互按本规格单独验证。
5. 自动化测试默认不调用真实付费 provider、不使用真实聊天或凭据；如需人工实测模型和取消计费，另行获得同意并列明验证范围。

### 验收清单

| 编号 | 操作与条件 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 创建项目任务、无项目任务，编辑资料，关闭并重开存储 | 元数据、列、关联、排序和共享版本保留；无项目身份正确 |
| T02 | 多选关联、同项目不同工作目录、跨项目及无项目混合请求 | 合法关联成功；越界拒绝；失败不造成重复归属或部分错误迁移 |
| T03 | 对话运行时改绑、结束后改绑、解除关联 | 运行中拒绝；停止后验证项目；提示旧历史保留；不再采用旧任务待更新版本 |
| T04 | 复制/新建分支 session、原会话内切换分支、普通空白聊天 | 新 session 正确继承任务；同 session 不新增关系；空白聊天不自动关联 |
| T05 | 初始列、改名、重排、增加列、删列 | 五列默认正确；新增均未完成；完成身份不变；完成列和最后未完成列受保护 |
| T06 | 删除包含可见、隐藏和归档任务的列 | 先明确接收列；全部任务一致转移；失败不留半完成结果；转入完成列有明确含义提示 |
| T07 | 列内/跨列/空列拖动；筛选后拖动；保存请求失败 | 正确持久化；不丢隐藏任务；错误可回滚/同步；没有模型请求 |
| T08 | 手动/自动排序切换，跨列移动，组合并保存筛选 | 自动排序禁用列内调序；仍可改状态；手动顺序不损坏；保存条件可重用 |
| T09 | 打开看板、任务详情、准备新对话、选择旧对话 | 卡片与详情字段齐全；不自动发消息；用户真正发送后才开始工作 |
| T10 | Agent 开始、等待、失败、停止、声称完成 | 仅运行提示变化，任务状态不变；用户移列才改变任务状态 |
| T11 | 同任务并行运行，包括同代码目录 | 允许并行；同目录先提示风险；不宣称已有自动隔离或合并 |
| T12 | 正常归档/恢复，运行中归档，启动与归档竞争 | 历史保留且恢复正确；忙碌时拒绝；无隐式停止或完成；不能从另一入口绕过归档运行约束 |
| T13 | 打开页面、切换对话、运行结束，与主动点击整理对照 | 前者无自动整理请求；后者进入选择、预览与模型确认流程 |
| T14 | 选对话、选部分工具结果、删减预览，包含附件/路径/未选记录 | 模拟模型只收到预览批准的文字范围；不读取附带路径或扩大到其他项目、分支、附件和日志 |
| T15 | 聊天/看板发起整理，临时换模型、模型不可用 | 默认模型正确；临时选择不污染设置；不可用不偷偷改 provider；来源会话不执行工具或新增普通消息 |
| T16 | 生成摘要、编辑、取消、确认、查看历史、恢复 | 未确认不共享；确认生成可追踪版本；恢复不删除版本历史；失败保留旧确认内容 |
| T17 | 两标签页同时发布共享版本或同时移动同一任务 | 冲突可见；不会静默覆盖；重试不重复创建任务或版本 |
| T18 | 新任务对话首次发送；已有对话不接收与主动接收更新 | 新对话用明确最新确认版本；未接收不更新；采用版本和来源可查 |
| T19 | 运行中接收更新、自动继续/已有队列、之后再发布更晚版本 | 当前工作不被干预；下次用户发送才用所选版本；不自动跟随之后更晚版本 |
| T20 | 共享接入普通、Chat-only、压缩后与分支会话 | 保留原资源权限、精确系统提示、有效历史和工具配对；已采用信息与版本可追踪 |
| T21 | 断网、重开页面、服务重启、大量任务和长会话 | 回到正确持久状态；不为每张卡读取全部正文或启动 Agent；失败不伪装成功 |
| T22 | 未授权请求、跨范围 ID、任意文件路径、共享内容中的指令 | 既有访问规则有效；ID/路径不自动授权；共享资料不能代替用户确认操作 |
| T23 | 键盘、触摸、小屏、当前最低 Safari 与桌面浏览器 | 核心移动、筛选、预览、确认、归档流程可用，不仅鼠标拖拽可操作 |
| T24 | Windows/macOS 项目身份和生产安装方式 | 项目比较、持久化、选定依赖和分发可用；结果单独记录，不能由开发机通过推断 |

测试失败不能标记相关票据完成。实现交付应报告真正执行过的检查、未执行的平台和真实 provider 验证缺口，不把本节计划当作已通过证据。

## Out of Scope

- 多人账号、团队分工、跨用户访问控制与协同编辑。
- 完整 Jira 报表、可自由布局的小组件、周期管理、工时或统计仪表盘。
- 跨项目任务、跨项目对话关联，以及一个对话同时归属多个任务。
- AI 自动聚类或推荐历史对话归属。
- AI 自动改变任务状态、自动确认完成、拖动触发执行和后台自动调度。
- 自动为对话创建独立代码副本、自动合并修改，以及对同目录并行写入的安全保证。
- 看板和聊天并排显示。
- 每个项目独立配置列、多个完成列和按列名推断完成。
- 任务彻底删除，以及归档自动停止 AI。
- 自动总结每轮回复、未经确认传播摘要、实时合并原始对话历史。
- 默认读取附件/文件全文、全局扫描私密历史、保证完全自动脱敏。
- 向量数据库、知识图谱或第三方 memory 服务作为第一版必需依赖。
- Jira、Linear、Plane、Beads 等外部任务源的导入或双向同步。
- 新增可直接修改任务状态的 Agent 工具；现有 todo 不被替换为长期任务数据库。
- 自动提交、推送、发布远程 issue/标签/Gist 或自动启动实施子代理。

### 实施纪律与风险

- 原访谈记录保存用户选择；研究报告是参考，不是功能合同。本规格在正式实现时还需配套更新分支功能合同和相应验收项。
- 第一版范围是本规格的完整闭环。可以分阶段交付，但不能把共享版本、筛选保存或其他已确认能力悄悄改为未承诺的远期功能。
- 技术验证应先覆盖拖拽与旧浏览器、存储与生产分发、共享信息与真实 SDK 生命周期三处风险。由其结果决定具体库和模块细节。
- 浏览器显示已更新不等于模型已经采用新信息；应以实际发送时使用的版本为准。
- 同目录提示不是文件隔离；改绑不是遗忘；归档不是停止；任务完成不是 Agent 停止；确认摘要不是证明摘要绝对正确。
- 本次仅生成规格和同步需求记录，不运行应用测试、不调用真实模型、不创建具体实施票据、不开始实现。后续测试需在隔离数据下进行，不能污染正在使用的开发服务和真实会话。
